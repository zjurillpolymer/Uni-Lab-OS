物料状态、条码与内容物¶

阅读角色

  • 业务负责人：确认物料名称、规格、容量、放置规则、条码和现场状态。

  • 开发人员：实现物料模板、放置位约束、启动图实例和工作流资源合同。

  • 验收人员：核对实物兼容性、位置关系、数量变化、搬运和异常恢复。

物料模板回答“这类物料的固定规格是什么”，物料状态回答“现场这一件物料现在是什么情况”。本页说明条码、液体、固体和自定义状态应该怎样保存，避免重启后丢失或同一数据在多个位置互相冲突。

本页完成条件

同一件实物具有唯一身份；条码、当前位置和内容物能够保存并恢复；液体与固体使用统一单位；动作失败或结果不确定时不会提前改写库存事实。

2. 内容物和单位规则¶

当前代码对内容物采用统一单位：液体使用微升 µL，固体使用微克 µg。对外页面可以同时显示 mL 或 mg，但写入系统前必须完成单位换算。

1 mL = 1,000 µL
1 mg = 1,000 µg

  • max_volume 表示容器最大容量，单位 µL；

  • 当前液体组成和历史变化属于实例状态，不属于模板规格；

  • 不知道物质名称时可使用系统的未知物质规则，但后续确认后要完成更正和追溯；

  • 取液不能让当前量变成负数，加液不能超过允许容量；

  • 同时操作多个孔位时，物质名称、用量和目标位置的数量必须一一对应。

3. 保存自定义运行状态¶

自定义资源可以通过 serialize_state() 返回需要持久保存的状态，并通过 load_state() 恢复。状态只能包含 JSON 支持的基础数据：文字、数字、真假值、空值、列表和键值表。

不要保存以下内容：

  • 打开的串口、网络连接或文件对象；

  • Python 类实例和不能转成 JSON 的对象；

  • 可以从固定规格重新计算出的重复数据；

  • 密码、令牌和不应进入库存的敏感实验数据；

  • 同一事实的第二份副本，例如同时在 config 和 data 保存两个不同条码。

构造函数必须能够接收资源保存后再次加载时返回的字段。新增重要状态字段时，要同时验证“保存→重启→恢复→再次保存”的完整往返过程。

4. 动作什么时候更新状态¶

动作结果

库存和物料状态

设备明确成功

一次性提交内容物或位置变化

设备明确失败且未动作

保持原状态，记录失败原因

超时、断线、结果不确定

保持原事实，标记待人工核对

人工确认已完成

按确认结果补记变化，并保存确认记录

重试请求

先查询原任务，避免重复加液、取料或搬运

5. 交付前必须检查¶

  • 同一个条码不会同时对应两件有效物料；

  • 模板编号、实例编号和条码三者没有混用；

  • 容量和质量换算有自动测试；

  • 多孔物料能够按位置读取和保存内容物；

  • 系统重启后条码、内容物、历史和当前位置保持一致；

  • 失败、超时和人工修正都留有可追溯记录。
