文档适用范围与版本管理¶

阅读角色

  • 业务负责人：确认版本、适用范围和验收结论。

  • 开发或运维人员：记录设备包、启动图、环境和外部组件信息。

  • 验收人员：核对证据完整性，并在配置变化后重新判定受影响能力。

本手册描述 Uni-Lab OS 的通用接入方法。具体设备、物料、工作流、地址和可用能力由用户安装的设备包与本次启动图（Graph JSON）决定，不能从文档示例推断现场已经具备某项能力。

每次安装要记录什么¶

项目

记录内容

Uni-Lab OS

版本号或发布标识

用户设备包

包名、版本号和交付日期

启动图

文件名、用途和校验值

运行环境

操作系统、Python 版本和运行模式

外部组件

仿真器、PLC、厂商服务及其版本

验收结果

测试工作流、时间、执行人和结论

这些信息应进入项目的受控交付记录，不要把内部下载地址、访问令牌、人员账号或生产密码写进公开文档。

能力状态怎么表达¶

状态

含义

已定义

代码中有设备、物料或工作流定义，但尚未证明本次安装已加载

已加载

检查报告和运行状态能够找到对应对象

已联调

在隔离环境中完成了协议或单设备测试

已验收

按正式配置和业务标准完成验收

“已定义”不能写成“可生产使用”，“服务运行”也不能代替设备在线和工作流验收。

信息冲突时的处理顺序¶

出现文档、设备包和运行页面不一致时，先停止危险动作，再依次核对：

  1. 本次批准使用的版本记录；

  2. 实际安装的设备包检查报告；

  3. 当前 Workspace 与 启动图；

  4. Uni-Lab OS 中的在线设备和任务执行记录；

  5. 设备包随附的部署与安全说明。

不能通过修改展示文字掩盖配置差异。确认原因后，应修正配置或代码并重新验收。
