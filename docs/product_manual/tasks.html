任务与并行调度¶

阅读角色

  • 业务负责人：确认实验目的、输入输出、参数单位、成功标准和失败处理。

  • 开发人员：编写或编排节点、物料流、控制结构、设备绑定和正式合同。

  • 验收人员：执行静态检查、预检、模拟运行、异常路径和受控真机验收。

任务页是实验运行期间的主要操作入口。每一行代表一次工作流运行，每一列代表该任务冻结执行图中的一个节点。

读取任务矩阵¶

顶部汇总卡片显示运行中、等待资源、今日完成和需要处理的数量。使用“全部、运行中、等待、异常、已完成”筛选任务。

矩阵中的常见节点状态：

  • 绿色完成：节点成功；

  • 蓝色运行：设备 Job 正在执行；

  • 橙色等待：依赖、设备、物料、库存或工位尚未满足；

  • 红色失败：动作或运行语义失败；

  • 灰色未运行：节点尚未就绪，或所在分支未被选择。

点击任务行可以查看样品/描述、当前节点、整体进度和更新时间；点击节点可查看实际参数、return_info、feedback_data 和错误。

理解“等待”¶

等待不是错误。多个任务共享机械臂、工站或同一库位时，Uni-Lab OS 会用资源锁将冲突动作串行化。打开“阻塞与异常”区域，检查：

  • 正在占用资源的任务或 Job；

  • 等待的设备、物料或站点；

  • 库存预留不足；

  • 前置节点或人工确认；

  • Uni-Lab OS 中的设备连接和可派发状态。

处理根因后点击刷新。不要因为等待就重复创建同一任务。

人工确认¶

工作流中的 manual confirmation 会在任务页显示确认内容和倒计时。操作员应：

  1. 打开确认项，阅读动作、上下文和风险；

  2. 到现场完成要求的核对；

  3. 选择批准或拒绝，并按要求填写说明；

  4. 观察任务是否进入下一个状态。

超时或没有反馈不会自动视为批准。

单步运行与任务控制¶

在 develop 模式中，可以对未结束任务执行：

  1. 暂停或切换为单步；

  2. 等待在途 Job 结束；

  3. 从多个可执行节点中选择下一步；

  4. 执行下一步并核对结果；

  5. 恢复自动运行，或取消任务。

product 模式不展示这些单步控件。API 支持在产品模式取消任务，但 Uni-Lab OS 页面的取消按钮位于开发模式控制区；产品模式下需要由管理员通过 API 执行并核对结果。

并行运行¶

并行调度需要 product 模式。多个任务可以同时处于运行态，但具体节点只有在所有依赖、设备、物料、工位和库存条件满足时才会派发。

例如，两个任务可以使用各自的源材料和独占库位，同时共享机械臂和多个工艺站。Uni-Lab OS 允许无冲突节点并行，对共享资源的节点排队，不要求用户手工安排时间片。

Trace 与动作日志¶

任务存在 trace_id 时，可以从详情打开 SigNoZ。建议按以下顺序排查：

  1. 从任务找到失败或长时间等待的节点；

  2. 查看 Job 参数、feedback 和错误；

  3. 打开 Trace 对齐 Uni-Lab OS 内部的调度与设备执行 span；

  4. 再按设备、变量和时间查看 用户设备包 动作日志中的 ACTION、STEP、PLC-CALL、WAIT、WRITE、READ 或 HTTP 标记。

用户设备包 本地短 trace 可能在跨线程 PLC 调用时显示 -，它不等同于 OpenTelemetry Trace。

高风险恢复操作¶

强制释放执行锁¶

只有已确认设备安全停止、物料现场位置明确时才可使用。操作需要精确匹配 holder/claim、fencing 信息，填写原因并确认物理状态。释放锁还可能取消当前或排队 Job，但不会让已经发生的物理动作回退。

结算失败的物料转移¶

如果物理转运发生后软件未能提交位置，任务可能要求人工结算：

  1. 现场确定物料实际所在站点；

  2. 选择真实站点；

  3. 填写原因并确认；

  4. 等待库存台账和执行锁一起收敛。

不要根据“原计划目标”猜测位置。

解决 execution_unknown¶

机械臂或 Uni-Lab OS 的设备连接在动作中断线/重启后，结果可能变为未知。系统不会自动重发，因为原动作可能已经执行。先用只读状态、传感器和现场检查对账，再在原任务的恢复入口提交带原因和唯一 resolution ID 的决定。

处理干预项¶

当工作流产生 intervention 时，在详情中选择后端给出的合法选项。选择会写入审计记录并推动原任务；不要另建替代任务绕过干预。

危险

任何“重试、跳过、强制释放、人工结算、解决未知结果”都可能改变之后的物理动作和库存事实。只有授权操作员在现场状态明确时才能执行。
