# SZLab 场景指南

SZLab 是当前环境加载的聚合物实验室设备包。它把 S04–S09 工艺站、机械臂、PLC、物料模板、仓库布局和实验工作流注册到 Uni-Lab OS。

运行任何 SZLab 流程前，先完成[运行模式、安全与恢复](runtime-safety.md)和[PLC-Sim 仿真器](plc-sim.md)中的前置检查。共享演示环境经过真实 Driver 调用链，但当前 PLC 端点仍是模拟器；这不代表真机已经验收。

### 可复用实验操作

“SZLab 标准物料转运”是当前发布目录中的 `experiment_operation`，不是独立工艺结果。上层工作流调用它完成标准 pick/place，并在物理成功后唯一一次提交物料位置。

## 单样品完整流程

不同变体的具体节点略有差异，机器人原子动作版本的主流程为：

1. 解析烧杯、粗/精粉桶、双路溶剂、试剂瓶、吸头盒和样品瓶来源。
2. 将烧杯搬到 S07，执行双粉投料。
3. 搬到 S06，加入双路溶剂。
4. 把液体试剂瓶送到 S08 开盖，再送到 S09 移液，之后关盖并归位。
5. 把烧杯送到 S04 搅拌，再回到 S09 测密度。
6. 将烧杯送到 S05 拍照，同时在 S08 打开样品瓶。
7. 机械臂执行取杯、倒液和放回的原子组合动作。
8. 关闭成品样品瓶，经过 S11 存放；可重复仿真版本再把可复用物料返回起始库位。
9. 提交试剂数量消耗，输出成品瓶、物料引用、密度和过程结果。

## 运行前准备

先按[PLC-Sim 仿真器](plc-sim.md)只读确认 OPC UA Server、SZLab 握手代理和 Edge Session 均已就绪，再进入工作流“运行准备”。

在工作流“运行准备”中至少核对：

- 样品 ID 与本次实验说明；
- 目标投粉质量及允许范围；
- 两路溶剂量和移液量/单位；
- 烧杯、样品瓶、粉桶、试剂瓶和吸头盒的真实来源；
- 所选库位没有重复、占用或现场不一致；
- 试剂可用量大于本次数量要求；
- PLC、机械臂和涉及的 S04–S09 工位可派发；
- 工作流引用的是预期的已发布修订。

预检通过后再次到现场核对容器和工位，再创建任务。

## 运行 A/B 并行任务

当前环境启动在 `develop`，先在没有活动任务和模式阻塞项时切换到 `product`。然后：

1. 为 A 与 Task B 分别选择各自的烧杯、样品瓶、粉桶、试剂瓶和独占源库位。
2. 确认共享溶剂和吸头库存足以覆盖两个任务。
3. 分别执行预检；任何一个出现来源重复或库存不足都先修正。
4. 先后提交两个任务，并在任务矩阵观察它们同时存在。
5. 对共享机械臂、S06、S08、S09、S05 和工位产生的等待应视为正常仲裁。
6. 只有无冲突节点可以并发；不要人工强制释放共享资源来追求“同时运行”。

`develop` 模式会拒绝第二个开发任务，错误通常表现为 `develop_task_conflict`。切换模式不会把已有任务迁移成产品任务。

## 正确理解结果

| 输出 | 应如何理解 |
| --- | --- |
| `product_vial`、`used_beaker` 等 | 任务结束时库存台账中的物料引用和位置。仍需与现场核对。 |
| `commanded_powder_mass_g` | 下发给投粉动作的目标/指令质量，不是最终实测质量。 |
| `density` / `density_unit` | S09 密度流程计算结果；需结合秤和移液站校准状态。 |
| `photo_path` / `inspection_result` | 当前 S05 相机 URL和算法未正式接通，不能据此承诺真实图像或自动判定。 |
| Trace | Scheduler 与 Edge 的执行链路，不等于工艺质量报告。 |

S07 驱动可以把称量采样写入 `samples.csv` 和 `balance_curves.svg`。记录文件写入失败只告警，不一定让工艺动作失败；最终读取秤失败才会导致验证失败。因此“任务成功”“历史附件存在”和“称量符合工艺要求”是三个需要分别确认的事实。

## 真机使用前

设备包默认面向离线/测试联调。真机上线至少要逐项完成 IP 与 NodeId、账号、只读映射、握手校准、机器人点位、传感器语义、库位映射、容量、超时、取消、断线、急停和 UNKNOWN 对账验收，并按单站、跨站、完整流程逐级放行。
