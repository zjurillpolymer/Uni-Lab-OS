认识 Uni-Lab OS¶

Uni-Lab OS 是面向实验室自动化的统一运行与管理平台。它把设备、物料、试剂、实验操作、工作流和执行任务放在同一套业务模型中，让实验从资源准备、流程设计，到自动执行和结果追溯形成完整闭环。

简单来说，Uni-Lab OS 不只负责“让设备执行一个动作”，还要回答以下问题：

  • 这次实验需要哪些设备、物料和试剂，它们当前是否可用；

  • 每一步要做什么、使用哪些参数，前后步骤如何衔接；

  • 多个任务同时运行时，谁可以使用某台设备或某个工位；

  • 执行到了哪一步，设备返回了什么，异常后应如何处理；

  • 实验结束后，能否查清使用了什么、执行了什么，以及得到什么结果。

从准备到追溯的业务闭环¶

Uni-Lab OS 将一次实验组织为五个连续阶段：

  1. 准备资源：登记物料和试剂，确认库位、数量、状态以及设备是否在线。

  2. 设计实验：将设备动作组合成可复用的实验操作，再将实验操作编排为完整工作流。

  3. 运行前检查：检查输入参数、设备、物料、试剂、工位和库存是否满足执行要求。

  4. 调度与执行：创建实验任务，由系统拆分具体动作、占用所需资源，并按依赖顺序下发执行。

  5. 记录与追溯：保存任务进度、设备反馈、人工确认、异常处理、物料变化和实验结果。

设备、物料与试剂准备 → 实验操作设计 → 工作流编排与发布 → 创建任务并预检 → 自动调度与执行 → 查看结果与追溯记录

八项核心能力¶

设备管理¶

系统统一识别设备及其业务动作，并记录在线状态、动作参数、执行反馈和状态变化。例如，一台移液设备可以提供“吸液”“排液”等动作，每个动作都要明确体积、速度、位置等参数的名称、类型、单位和允许范围。

设备能够执行哪些动作，由用户准备的设备包定义。设备包加载后，可通过系统接口或获准使用的调试工具进行单动作测试。设备显示“在线”只代表通信可用，不代表所有动作已经完成现场安全验收。

试剂管理¶

系统分别管理“试剂是什么”和“这份试剂在哪里、有多少”：

  • 试剂档案记录名称、标识、规格等身份信息；

  • 试剂库存记录承载容器、当前位置、数量、浓度、单位和批次信息；

  • 分装、转移、消耗和调整形成可追溯记录；

  • 工作流可按规则预留和扣减库存，避免同一份试剂被多个任务重复使用。

数量和浓度必须带有明确单位。自动扣减反映系统账面变化，不代替称重、液位或其他现场检测。

物料与库位¶

物料模板描述一类物料应具备哪些字段、容量、槽位和约束；物料实例表示现场某一个真实对象，例如一块孔板、一个吸头盒、一个样品瓶载架或一个弹夹。

系统可记录物料的唯一标识、条码、父子关系、当前位置和历史变化。例如，“样品瓶位于载架第 3 个槽位，载架位于上料工位”。上料、移动、下料和盘点时，应同时更新现场状态和系统记录，不能只修改页面数据。

实验操作¶

实验操作是可重复使用的一段标准实验步骤。它可以组合多个设备动作，并加入条件判断、重复执行、人工确认和其他已发布操作。

适合复用的步骤应先整理成实验操作，例如“取样并加入反应容器”或“检测并保存结果”。这样，同一段操作可被不同工作流调用，修改和验证也更集中。

工作流管理¶

工作流描述一项完整实验如何完成，包括输入、输出、执行节点以及节点之间的先后依赖。业务人员可以查看、导入、编辑、检查和发布工作流；流程设计人员需要为每个输入和结果说明名称、用途、数据类型、单位、是否必填以及允许范围。

工作流发布后形成稳定版本。已经创建的任务继续使用创建时对应的版本，不会因为之后再次编辑而悄悄改变。正式运行前，应先完成结构检查、参数检查和隔离环境验证。

任务执行¶

一次工作流运行称为 Task（任务）。系统会把任务拆分成若干 Job（执行步骤），再将每个步骤派发给对应设备。

在任务执行过程中，可以查看整体状态、当前步骤、设备反馈和结果；遇到需要人员判断的环节，可处理人工确认；出现已知异常时，可按获准规程停止、恢复或处理。对于设备已执行但系统未收到明确结果的情况，必须先核对现场，再决定如何结算，不能直接重试可能产生二次动作的步骤。

并行调度¶

系统可以同时管理多个实验任务，并通过资源锁和库存预留避免冲突：

  • 设备、物料或工位被一个任务占用时，其他任务等待；

  • 前置步骤完成并释放资源后，满足条件的任务自动继续；

  • 维护或异常处理期间，可停止新的任务派发，再在确认安全后恢复；

  • 调度记录可用于查看任务等待、占用和释放资源的过程。

“并行调度”表示系统可以同时安排不存在资源冲突的任务，不表示同一台物理设备能够同时执行多个动作。真实并发能力必须以设备、工艺和安全联锁的验收结果为准。

日志与记录¶

系统保留与实验执行相关的业务记录，包括任务和步骤状态、设备动作与反馈、人工确认、工作流版本、物料位置变化、试剂库存变化和处理结果。按部署配置启用追踪能力后，还可以关联一次请求在不同执行环节中的记录。

日志用于还原“系统当时收到和处理了什么”，不能替代现场检查记录、法定审计材料或仪器原始数据。需要长期保存的数据，应按组织的数据管理制度设置归档和备份。

两条常用业务流程¶

流程一：实验设计与调试¶

  1. 在设备包中定义设备连接方式、业务动作、动作参数和返回结果。

  2. 在安全环境中确认设备上线，并逐项测试动作及失败处理。

  3. 创建实验操作，将已验证的动作组合成可复用步骤。

  4. 编排完整工作流，设置输入、输出、条件、循环和步骤依赖。

  5. 执行结构检查、运行前检查和模拟或隔离测试。

  6. 审核通过后发布稳定版本，供实验任务选择。

流程二：实验任务执行¶

  1. 准备物料和试剂，完成上料、位置和数量核对。

  2. 选择已发布且适用于当前场景的工作流。

  3. 填写实验参数并绑定本次使用的物料、试剂和工位。

  4. 通过运行前检查后创建任务。

  5. 由 Uni-Lab OS 分配资源、调度设备并执行各步骤。

  6. 查看进度，按规程处理人工确认和异常。

  7. 核对执行结果、资源变化和追溯记录，完成实验收尾。

先理解六个核心对象¶

对象

业务含义

典型内容

设备与动作

现场设备以及设备可以完成的业务能力

设备标识、连接状态、动作名称、输入参数、返回结果

物料

实验中被放置、承载、搬运或处理的实物

孔板、吸头盒、容器、载架、弹夹、样品容器

试剂

试剂身份及其实际库存

名称、批次、容器、数量、浓度、单位、位置

实验操作

可重复使用的一组实验步骤

设备动作、条件、循环、人工确认、子操作

工作流

面向完整实验目标的流程版本

输入、输出、节点、依赖、发布版本

Task 与 Job

一次实验运行及其具体执行步骤

任务状态、步骤状态、设备反馈、结果、异常处理

这些对象之间的关系可以概括为：

设备提供动作；物料、试剂和库位提供实验资源；实验操作组合动作；工作流组织操作；Task 启动一次工作流；Job 执行其中的具体步骤；日志与记录贯穿全过程。

用户设备包的作用¶

Uni-Lab OS 提供统一的管理、预检、调度、执行和记录能力，但不会预先知道某个实验室有哪些设备、物料和工艺。用户需要准备与现场一致的设备包，至少说明：

  • 设备：有哪些设备实例，如何连接，每台设备提供哪些动作；

  • 动作合同：每个动作接收什么参数、返回什么结果、如何超时和报错；

  • 物料模板：现场使用哪些物料类型，各自有哪些字段、容量、槽位和约束；

  • 启动图：本次环境要加载哪些设备和资源实例，它们如何连接和定位；

  • 实验操作与工作流：现场批准执行的步骤、顺序、输入、输出和异常处理方式。

安装 Uni-Lab OS 后，还需要安装或挂载用户自己的设备包，并通过启动图加载当前实验室的实际配置。设备包定义的是“系统应当认识什么”，启动图定义的是“这次启动具体加载什么”。两者缺一不可。

设备包的目录、配置和检查方法见设备包规范与系统启动。从零部署产品时，先完成系统安装。

使用边界¶

为避免把“系统记录正确”误解为“现场一定安全”，使用时必须遵守以下原则：

  • 系统中的库存、位置和设备状态需要通过现场操作或设备反馈保持同步；

  • 运行前检查只能发现系统已知的问题，不能代替机械限位、急停和安全联锁；

  • 模拟运行通过不等于真实设备已经验收，真机动作必须逐项测试；

  • 工作流可执行不等于工艺已获批准，发布和运行权限应分开管理；

  • 异常恢复前必须确认设备、物料和试剂的真实状态，避免重复投料、重复移动或重复检测。

建议的首次使用顺序¶

如果已有可用环境，先阅读使用 Uni-Lab OS，再按体验已部署的安全工作流熟悉页面和任务过程。

如果需要从零建设环境，按以下顺序进行：

  1. 系统安装

  2. 设备包规范与系统启动

  3. 环境与运行配置

  4. 设备与动作

  5. 工作流基本概念

完成安装、设备包加载和现场验收后，才进入正式实验运行。
